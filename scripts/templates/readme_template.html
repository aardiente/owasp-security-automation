01 / Introduction

What this framework does

This project combines browser-based tests, direct API requests, disposable application containers, OWASP ZAP observations, and screenshot evidence. It is designed for intentionally vulnerable training applications rather than for production scanning.

OWASP Juice Shop

Challenges

Runs automated challenge tests covering input handling, authentication, resource exposure, administrative controls, and related weaknesses. Splits HTTP-driven and browser-driven challenges, captures evidence, and checks challenge completion.

Primary suite: testng-juiceshop.xml

DVWA

Security levels

Exercises SQL injection, reflected and stored XSS, command injection, file inclusion and file upload across DVWA security levels. Tests can deliberately fail to report observed security weaknesses.

Primary suite: testng-dvwa.xml

Results terminology: A passing Juice Shop challenge test generally means the expected challenge behavior was verified. A failing DVWA security assertion may indicate that a vulnerability was observed; examine the assertion and evidence. A ZAP alert is a scanner observation, not independently validated proof of exploitability.
02 / Setup

Install and run

Prerequisites

  • JDK 17+ (the Maven compiler source and target are Java 17).
  • Maven or IntelliJ IDEA with Maven support.
  • Docker Engine accessible to your OS user and IDE.
  • Google Chrome for the project's default ZAP-proxied browser tests.
  • Initial network access to obtain Maven dependencies and Docker images.

First run

1

Open the extracted project root (the folder containing pom.xml) in IntelliJ.

2

Allow Maven to import dependencies and ensure Docker is running.

3

Review src/test/resources/config.properties for browser and scan limits.

4

Run the desired testng-*.xml suite from IntelliJ, or use Maven as configured below.

Running from Maven

The project README documents the following suite selection pattern. Your Maven/IDE TestNG configuration must support the suite XML setting.

mvn test -Dsurefire.suiteXmlFiles=testng/testng-juiceshop.xml
mvn test -Dsurefire.suiteXmlFiles=testng/testng-dvwa.xml
mvn test -Dsurefire.suiteXmlFiles=testng/testng-zap-active.xml
mvn test -Dsurefire.suiteXmlFiles=testng/testng-zap-dvwa-active.xml

To launch the read-only dashboard, run the utilities.reporting.SecurityAssessmentSpa main method from your IDE. The configured address is http://127.0.0.1:8765/.

Presentation-friendly: You can run each scanner before your demonstration, keep the report JSON and screenshots, and start the SPA later. Opening the SPA does not run Docker, Selenium, or ZAP.

Responsibility boundaries

  • ZapManager manages the proxy and ZAP report export.
  • ZapActiveScan initiates a bounded crawler and active scan.
  • ScreenshotManager records evidence tied to test runs.
  • FindingFilter applies reporting scope and review/suppression rules.
  • SecurityAssessmentSpa reads saved artifacts through a loopback HTTP server.

07 / Output files

Where the findings are saved

The configuration sends JSON reporting artifacts to target/security-reports/. Passive and active scanning use distinct filenames, so running one suite should not replace the other suite's report. Running a suite again replaces that suite's previous output.

Other artifacts

Regular TestNG CSVStandalone scan TestNG CSVScreenshot evidenceNative ZAP HTMLGenerated static HTML assessments

The SPA reads existing files; it does not verify that every JSON, CSV, and screenshot came from the same execution. Preserve the relevant report snapshots together when presenting them.

Do not clean away your demo data. Maven's clean lifecycle normally deletes target/, including saved scan results and screenshots. If using previously recorded findings for a presentation, keep an independent copy of the report artifacts.
08 / Diagnostics

Common issues

SymptomInterpretation or check
Active card says Not runCheck that the matching active status JSON exists under the configured ZAP report directory, then refresh the SPA.
DVWA findings are missingVerify the DVWA suite reached report generation and that the JSON site origin matches target.dvwa.site. The SPA's scope filter excludes other origins.
CDP version warning from ChromeSelenium may use its nearest available CDP implementation. This is a compatibility warning; it is not, by itself, proof of a test failure.
Node with given id does not belong to the documentChrome saw a DOM node replaced during a WebDriver interaction. Inspect the current page and the DVWA setup/login lifecycle; this failure can occur before scanning starts.
TestNG cannot find a classVerify source location, Java package, suite XML class name, and successful compilation. Filesystem capitalization matters on Linux.
Findings load but none are in scopeCheck the ZAP JSON host and explicit/default port against reporting target configuration. Review any configured review/suppression rules.
ZAP scan times outThe configured deadline was reached; the generated status will report timed_out. Collected findings may be incomplete.
09 / Responsible use

Scope, validation, and known limitations

  • Use this project only against isolated, intentionally vulnerable lab instances and other systems with explicit permission.
  • Scanner alerts need validation. The SPA's INCLUDE, REVIEW, and SUPPRESS classifications reflect configured scope and triage rules; they are not automatic vulnerability confirmation.
  • DVWA page visits seed the ZAP Sites tree, but the standalone active scan is not necessarily configured to run as an authenticated DVWA user. Protected-page scan coverage may be limited.
  • CDP/browser driver compatibility and page timing can affect Selenium-based setup and test execution.
  • The SPA is read-only and intended for local loopback access. It should not be exposed publicly.
  • Saved report artifacts do not include a shared run identifier or guarantee matching timestamps between tests and screenshots.
  • Method documentation describes code in this uploaded snapshot. Code compilation and integration tests must be performed in the project's configured development environment before deployment or presentation.
